# DARAI — frontend

Реализован React + Vite + TypeScript интерфейс по `docs/API_CONTRACT.md` v1.0. Production всегда обращается к настоящему API. Фикстуры существуют только в `frontend/tests/e2e/` и подключаются перехватом запросов Playwright; переключателя «демо-успех» в приложении нет.

## Запуск

Подготовка с доступом к реестру пакетов (Node.js 22.12+ или поддерживаемый более новый Node):

```bash
cd frontend
npm ci
npm run dev -- --port 5173
```

Открыть `http://localhost:5173`. Backend по умолчанию должен отвечать на `http://127.0.0.1:8000`. Учётную запись создаёт backend; frontend не содержит встроенного логина или пароля.

Другой адрес **внутри контура** задаётся переменной процесса Vite, без изменения корневого `.env.example`:

```bash
BACKEND_URL=http://127.0.0.1:8001 npm run dev -- --port 5173
```

Браузер во всех случаях обращается к `/api`. `BACKEND_URL` не встраивается в JS приложения. Vite удаляет префикс `/api` и сохраняет исходный Host для same-origin/CSRF. `npm run preview` предназначен только для просмотра собранной статики: API-прокси production обеспечивает nginx, а не preview.

## Production и закрытый контур

Из корня репозитория на этапе подготовки:

```bash
docker build -t darai-frontend:local frontend
```

`frontend/Dockerfile`: сборка в Node 22 Alpine → только `dist/` и конфигурация в nginx 1.28 Alpine. Образ обслуживает порт **80**. Для Compose backend-агенту нужны `build.context: ./frontend`, общий network с сервисом `backend`, маршрутизация на `backend:8000` и публикация выбранного порта frontend. Корневой Compose frontend-агентом не менялся.

- `location /api/` → `http://backend:8000/`: завершающий `/` удаляет префикс.
- Остальные маршруты используют SPA fallback на `index.html`; API-ошибки не заменяются HTML приложения.
- Потоковая передача файла через прокси без полного буферизования; лимит nginx **1024 MiB**, таймауты загрузки/прокси **600 секунд**. Backend дополнительно проверяет собственные лимиты. Если `MAX_UPLOAD_MB` выше 1024, согласованно поднять лимит в `frontend/nginx.conf`.
- Клиент показывает прогресс XHR, отдельно ожидание проверки файла сервером, ошибки 413/422/503/сети/таймаута. Обычные JSON-запросы ограничены 45 секундами; загрузки — 600 секундами.
- `index.html` и API имеют `Cache-Control: no-store`; нет service worker и клиентского дискового кеша данных CRM.
- Access log nginx отключён, ошибки API-прокси не пишутся в error log: поисковые строки могут содержать персональные данные.
- Нет внешних API, CDN, web fonts, аналитики и телеметрии. Используются шрифты операционной системы с кириллицей/казахскими символами. Никакой загрузки пакетов при старте production-контейнера.
- Образы, npm-пакеты и Chromium для тестов загружаются **на подготовительном этапе**. Для изолированной машины заранее перенести готовый образ через `docker save` / `docker load`; не запускать сборку с ожиданием доступа к npm в закрытом контуре.

## Подключение API и состояние

Типы — `frontend/src/types.ts`; HTTP/CSRF, загрузки и экспорт — `frontend/src/api.ts`. Форматы сверены с контрактом и появившимися `backend/app/schemas.py` / `serializers.py` (чтение без изменений backend).

- `credentials: include`, серверная HttpOnly cookie-сессия. CSRF хранится только в памяти и восстанавливается из `GET /auth/me`; изменяющие запросы передают `X-CSRF-Token`.
- 401 очищает состояние текущего пользователя и показывает вход. Ошибочный пароль отображается в форме. HTML вместо JSON трактуется как ошибка подключения/прокси.
- Персональные данные и токены не записываются в `localStorage` или `sessionStorage`.
- API сохраняет сотрудников, встречи, голосовые профили, правки спикеров/саммари/поручений, выполнение и прочтение уведомлений. После обновления страницы данные запрашиваются заново.
- Видимость по роли — только удобство интерфейса. Проверки ролей, доступа по ID, приглашений, экспорта, аудио и CSRF обязан выполнять backend.
- Статус активной обработки запрашивается через маршрут recording каждые 3 секунды до `done`/`error`. Счётчик уведомлений и открытый центр уведомлений обновляются каждые 30 секунд. Каждый polling-цикл ставит следующий `setTimeout` после завершения предыдущего запроса; уход со страницы отменяет запрос и таймер. У счётчика и центра отдельные ограниченные циклы.
- Редактор встречи не опрашивает весь черновик во время ручных правок. Сохранение одного раздела не сбрасывает несохранённые поля другого.
- Несохранённые правки блокируют утверждение, экспорт, замену и повтор обработки записи; показано предупреждение, при закрытии/перезагрузке вкладки используется `beforeunload`. Переход по внутренней ссылке не открывает отдельный диалог: сначала сохранить или отменить правки.
- Подтверждение передаёт `draft_revision` и явное `acknowledge_incomplete`. При конфликте версия не утверждается; доступна загрузка актуального протокола для повторной проверки.

## Экраны

| Маршрут | Возможности |
| --- | --- |
| Экран входа при отсутствии сессии | Локальный логин/пароль, ошибки, текущий пользователь, выход |
| `/employees` | Серверный поиск по ФИО/должности/департаменту, пагинация, статус аккаунта и голоса |
| `/employees/new`, `/employees/:id` | Создание/правка ФИО, должности, департамента администратором; просмотр сотрудниками |
| Карточка сотрудника | Уведомление и согласие; MediaRecorder или файл `file` + `consent=true`; качество/несовместимость; перерегистрация и подтверждаемое удаление |
| `/meetings` | Поиск, пагинация, отдельные статусы обработки и утверждения |
| `/meetings/new` | Название, дата/время в IANA-зоне, повестка, до 200 участников; встреча создаётся до записи |
| `/meetings/:id` | Участники, повестка, загрузка аудио/видео, этап, ошибка и retry; защищённый аудиоплеер и транскрипт |
| Проверка в карточке встречи | Спикеры и предложения, many-to-one ручное сопоставление, неизвестные; саммари; добавление, правка, удаление поручений |
| Поручение в протоколе | Автор, исполнитель, срок, исходная формулировка срока, цитата, ссылки на реплики и переход к аудио; deep link `#task-ID` |
| Утверждение и экспорт | Явная отметка неполных данных, подтверждение публикации; DOCX/PDF с опциональным транскриптом, ошибки экспорта |
| `/tasks` | Только мои подтверждённые поручения, фильтры «В работе / Выполненные / Просроченные», изменение выполнения |
| `/notifications` | Тип события, прочитанные/непрочитанные, переход к объекту, отметка одного или всех прочитанными |

Дата создания встречи переводится в UTC именно из выбранной IANA-зоны, независимо от зоны браузера. Просрочка в UI берётся из backend-поля `overdue`; frontend не переопределяет серверный конец дня срока.

Отсутствующие исполнитель/срок/автор отмечаются как требующие уточнения. Ошибка извлечения имеет отдельное сообщение, не «поручений нет». Similarity и confidence показаны как числовые оценки без процентов «точности». Статусы `processing_status`, `approval_status`, `execution_status` разделены.

Микрофон доступен только в secure context (localhost или HTTPS) и при разрешении браузера. Поддерживаются выбранные браузером WebM/Opus, MP4 или Ogg; конвертация — на backend. Захват ограничен 60 секундами, дорожки останавливаются после записи и при уходе. Ожидание разрешения можно отменить; опоздавший поток сразу закрывается. Во время записи загрузка/удаление заблокированы. Физический микрофон пользователя автоматически не включался при проверке.

## Проверки

Команды из `frontend/`:

```bash
npm run typecheck
npm run build
npm run test
# Подготовить Chromium заранее при отсутствии в локальном кеше:
npx playwright install chromium
npm run test:e2e
```

Проверено 23.09.2026 на macOS arm64, Node 24.8.0; production-сборка также прошла внутри Node 22 Alpine.

| Проверка | Результат и границы |
| --- | --- |

| Production bundle | `npm run build` проходит, локальные CSS/JS, без внешних ресурсов |

| Браузер | 8 сценариев Playwright на синтетическом API: полный путь, сохранение после reload, ошибка извлечения, ошибка загрузки, голосовой профиль, недоступный backend, роль/390px/401, конфликт версии, MediaRecorder с синтетической WebAudio-дорожкой |
| Полный путь UI | Вход → создание/правка сотрудника → встреча → загрузка → polling → спикеры → саммари → поручение → reload → утверждение → выполнение → уведомления → DOCX/PDF скачивание |

| agent-browser | Реальная Vite-страница при недоступном backend показывает ошибку и кнопку повтора, не пустую страницу и не фиктивные данные |

Фикстурные тесты используют только вымышленные данные. Запись обработки — тестовый ответ API, MediaRecorder проверен на синтетическом локальном аудиопотоке. Скачивание DOCX/PDF в фикстурах проверяет HTTP и браузерную загрузку **тестовых байтов**, а не валидность настоящего документа. Эти проверки не доказывают работу моделей, БД, серверной авторизации или качество RU/KZ ASR.

Скриншот сценария создаётся в `frontend/test-results/review-desktop.png`; каталог игнорируется git. Backend на `127.0.0.1:8000` во время проверки не отвечал; пользователь подтвердил, что его разработка продолжается. Секреты и реальные записи для тестирования не использовались.

## Сделано и оставшаяся интеграция

Сделаны все запрошенные экраны, типизированные запросы по контракту, cookie/CSRF, загрузки/микрофон, состояния ошибок/пустых списков, polling, ручная проверка, утверждение, задачи, уведомления, экспорт, Dockerfile и nginx. Изменения ограничены `frontend/**` и этим документом; коммит и push не выполнялись.

Для интеграционного завершения нужны:

1. Запущенный backend, PostgreSQL и тестовые локальные аккаунты admin/secretary/employee. Повторить сценарий через `/api` без перехвата Playwright и проверить серверное сохранение после перезапуска, ограничения ролей и чужие ID.
2. Подготовленные локальные ASR/диаризация/embedding/LLM; разрешённые RU/KZ/mixed-аудиофайлы и отдельные образцы регистрации. Проверить реальные quality-ошибки, неизвестного спикера, обработку, восстановление после сбоя и retry.
3. Реальный DOCX и PDF через LibreOffice: открыть файлы, проверить сохранённые правки и казахские символы.
4. Проверить runtime Compose и загрузку крупного файла через общий nginx/backend; backend-agent согласует свой `MAX_UPLOAD_MB` с пределом nginx 1024 MiB.
5. Проверить приглашение/назначение под разными аккаунтами, напоминания и просрочку на серверных часах, отсутствие дублей после повторного confirm и перезапуска.

Неразрешённых вопросов по полям/маршрутам контракта v1.0 сейчас нет. Блокер — доступность настоящего backend и подготовленного AI-окружения. Создание учётных записей, администрирование моделей, видеозвонки, live-stream и внешние интеграции не входят в эти frontend-экраны.
